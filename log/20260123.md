# 23 Jan 2026 – DeepSeek 3 – Hardware specs finalised and the LLM-as-compiler workflow

### Hardware spec

The hardware specification was locked: 25 signal IDs covering directional inputs, buttons, and encoders with clean naming (EA1/EA2/EAB for encoder pins and button). The software architecture on the C++ side is four classes — `Game` (timing, pixels, input hooks, defer system), `Strip` (NeoPixel abstraction), `Controller` (pin→signal mapping, debouncing, callbacks), and a `Components` library of Switch and Encoder drivers.

### The pipeline

The development pipeline is now three stages: Haxe for prototyping in the web simulator, LLM translation from Haxe to C++ in minutes, then C++ running natively on hardware. Wokwi handles hardware simulation without physical devices. MoodLight and STACK both run identically in the web simulator and on Arduino.

### C++ translation breakthroughs

Two technical breakthroughs made the C++ translation clean. First, the global callback pattern solved C++ member function callback hell:

```cpp
Game* gameptr = nullptr;
void onButtonAPress() { gameptr->buttonPress(Signal::BA); }
```

Second, hardware-aware translation rules — vectors become fixed arrays, string enums become integer enums, Haxe abstractions become direct hardware calls — mean the translated code is lean and has no STL dependencies.
