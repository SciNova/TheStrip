# 17 Nov 2026 17:21 – Claude Sonnet 5 – Synth+sampler audio engine built from scratch, wired through the project, proved out by rebuilding SimonSays sample-free

SimonSays needed real musical tones instead of pre-recorded samples. The project's only audio mechanism at the time was a per-game `<audio>`-element preloading class living inside `js/Console.js`, which had no way to produce a tone, so we designed and built a new audio engine from scratch before touching SimonSays itself.

### Audio engine design

The engine splits across the two realms the Web Audio API itself imposes. `core/audio-common.js` holds data shared by both sides: `Note`, an equal-tempered enum of named pitches, and `SampleID`, replacing the old ad-hoc `Sound` enum. `core/audio.js` is the main-thread host side — a `Sample` class doing real `fetch` + `decodeAudioData` + `Transferable` loading, thin postMessage-only `Synth`/`Sampler` proxies, and an `Audio` class tying them together. `core/audio-processor.js` is the `AudioWorkletProcessor` side, with its own independent `Clock`/`System` (objects can't cross realms, only messages can) and the actual DSP: `SynthSound` (sine/square/sawtooth generation by phase accumulation) and `SamplerSound` (linear-interpolated variable-rate playback of transferred sample data), both drawn from a fixed 10-slot voice pool with automatic allocation-or-oldest-eviction, or manual addressing via a `slot` parameter. There is no real browser on this device, so we verified almost entirely through throwaway Node scripts stubbing `AudioWorkletProcessor`/`currentTime`/`sampleRate`/`fetch`, and tested actual playback on a phone.

A `System.startAudio()`/`audioReady`/settle-delay mechanism seemed like the obvious way to gate game start until the sampler finished loading; we rejected it for inventing API surface nobody asked for, and used the existing `uptime` field directly instead — a flat `uptime >= 2.0` check in `System.loop()`, the threshold picked by printing the real host-side sampler-load time once and rounding up.

Early playback also produced one pop of audio and then silence; we traced it by comparing against `modplayer/mixer.js`'s working pattern to a missing `numberOfInputs`/`outputChannelCount` configuration on the `AudioWorkletNode` constructor, and fixed it by passing them explicitly.

### Wiring the engine in

From `system.js` we removed the dead `Sound` enum and stub `Audio` class, replacing them with `import { Audio } from './audio.js'`; from `js/Console.js` we dropped the legacy `SampleAudio extends Audio` override entirely, rather than reconciling it with the new class.

### Single-page menu

To let selecting a game from the menu also supply the user gesture `AudioContext` needs to start, we merged `index.html` and `game.html` into one page with a fading hamburger menu. The existing `<nav>` markup stayed as-is, with only `href="/games/X"` changed to `onclick="loadGame('X')"` — we dropped an earlier idea to parse game names back out of hrefs at runtime, in favor of each link just naming its own target directly.

### Folder reorganization

Every game, including drafts, ended up with a uniform `apps/{name}/{name}.js` path. The first attempt kept drafts' real files in `apps/drafts/{name}/` with symlinks at `apps/{name}` pointing in, later abandoned: we dropped the symlink layer entirely, moved `apps/drafts/*` out to a new top-level `drafts/` folder as a true sibling of `apps/`, corrected every moved file's relative import depth by one level, and changed `index.html`'s `loadGame`/`importGame` to take a full literal path per call (`'apps/Stack'` vs `'drafts/Pong'`) instead of searching anything. We rewrote all 45 nav links to match where each game actually lives on disk — in a few cases (`Bomberman`, `Breakout`, `Golf`, `MemoryMatch` are drafts; `Shooters`, despite sharing the same menu section, is not) that didn't match the menu's own section grouping — and trimmed `web.py`'s `GAME_SEARCH_DIRS` fallback list to match, from three candidate paths down to exactly `['apps/{game}', 'drafts/{game}']`, no fallback.

### Sound → SampleID rename

Removing the old `Sound` enum from `system.js` broke every game that referenced it — thirty-two files in total — and we first noticed it through `apps/Dices/Dices.js` failing to load. `index.html`'s `importGame()` turned out to have a try/catch/fallback loop across several search paths, masking the real import error behind a misleading "game not found" message; we removed that fallback outright rather than patching around it, then mechanically renamed all thirty-two files from `Sound.X` (string) to `SampleID.X` (number, imported from `audio-common.js` instead of `system.js`). SimonSays and Shooters stayed out of the sweep: SimonSays needed real synth tones, not a mechanical swap, and Shooters already has its own independent `CROAK`/`CROAK2`/`CROAK3` custom-sample scheme, which we left for a separate piece of work.

### Startup gate removed

The `uptime >= 2.0` gate we'd added earlier to let the sampler finish loading before `game.loop()` starts running came out as an experiment, to see whether it was still needed now that everything else was in place. The `uptime` field itself stayed, since it's still shown in the debug overlay in `js/game.js`.

### SimonSays rebuilt sample-free

SimonSays' four `SIMONSAYS1-4` sample calls and its `LEVEL_FAIL`/`LEVEL_COMPLETE` sample calls gave way to synth tones. Our first version held a tone on a dedicated slot for as long as a button was pressed, stopping it explicitly on release, and kept a `RESULT` stage to defer the correctness check. We simplified that across several follow-up passes: wrong-note presses now fail immediately, before the correct tone would even sound; we removed the `RESULT` stage entirely and resolved correctness directly on press (wrong note) or release (advance / level-complete); held-duration tones gave way to a fixed `duration` per note (0.3s) and no slot at all, since a self-expiring tone needs no explicit stop; and the fail/complete delay dropped from four seconds to one. The per-color pitch mapping went through a few iterations too — arbitrary pitches, then pitches matching the real 1978 Simon device's historical color assignment, then we settled on the simplest option: each button plays the note matching its own letter (`A4`/`B4`/`C5`/`D5`).

We also looked into the real 1978 Simon's exact playback tempo and its tempo-ramp at signals 5/9/13, but found no verified millisecond figures — even Hasbro's own manual documents that tempo ramps up without giving the actual values — so we dropped that approach in favor of just setting the interval to 0.4 seconds by feel, the same way we tuned every other timing value in the engine.

We closed the session by turning the per-button note mapping into a real feature: four interchangeable note sets — Normal, an "Arabic"-flavored augmented-second scale, a Chinese-pentatonic-derived set, and a "scary" four-semitone-step scale — all rooted on the same starting note (`A4`) so only the interval shape differs between them, switchable at any time with `LEFT`/`RIGHT` via a `noteSetIndex` that every tone looks up fresh at the moment it plays.

### Outstanding

`GAME_COMPLETE` in SimonSays is still intentionally on the sampler rather than the synth. The Shooters custom-sample mechanism remains unaddressed.
