# 17 Jun 2026 (b) – DeepSeek 3 Expert, Claude Sonnet 4.6 – Snapshots pipeline: .px stripshot format, snapshot() function, Keyboard rename, px2svg converter, snapshots.md output

The session started as a casual "what if" and became a complete asset pipeline in under half an hour. By the end, the platform had its own raw pixel format (`.px`), a capture function triggered by a single keypress, a renamed terminal input class, a zero‑argument conversion script that produces a Markdown file of SVG stripshots, and a corrected bullet‑trail gradient in Stack that slipped in along the way. No code was planned. All of it was designed, debated, and implemented live.

### The idea

We were in the middle of planning a testing sequence for the refactored C platform when the conversation took a hard left turn. The prompt was simple: what if a screenshot were just the raw RGB bytes of the strip – `resolution × 3` bytes, no metadata, no compression – and could be saved with a single keypress in the Python terminal simulator? The file extension would be `.px`, a custom format that is nothing but the truth of what the strip displayed at that exact moment. The name "stripshot" was coined on the spot: this was not a screen capture, it was a capture of the strip itself, and the name would stick.

### The `snapshot` function

The function began its life as a method on the `Strip` class, then moved to being a global function in the sketch, and finally landed as a standalone function in `system.py` taking a `System` object and a `datetime`. The label (game name or "system") is derived from the system state internally; the caller only provides the moment. The filename format locked in as `[label]-YYYYMMDDHHMMSScc.px`, where `cc` is centiseconds – two extra decimal digits that make same‑second overwrites vanishingly unlikely without adding any logic. The function opens a file in binary mode, walks the strip's pixel buffer, extracts R, G, B into a bytearray, and writes it. No return value, no error handling for overwrites, no hand‑holding. It does one job and does it silently.

The `datetime` import was already present; the function is self‑contained. The sketch calls `snapshot(system, datetime.now())` on the trigger key.

### The `Keyboard` rename

The terminal input class had been called `Input` since the Python reference was born. But `Input` is vague – it could mean buttons, encoders, touch, anything. The class is a keyboard driver: it reads raw terminal byte sequences and maps them to `Action` values. Renaming it to `Keyboard` made the hardware simulation layer self‑documenting. The file `hardware.py` was updated, and every reference to the old name in `sketch.py` followed.

### The PrtSc detour and the `s` fallback

The original plan was to bind the system's PrtSc key. On Android + Termux, PrtSc is captured by the OS for its own screenshots and never reaches the terminal. The key `s` was chosen as the practical fallback. In `Keyboard.process`, `'s'` is handled before the normal action mapping: it calls `snapshot(self.system, datetime.now())` and returns `None` – no game event, no game switching. The `_CHAR_MAP` entry for `'s'` was set to `None` so it is never accidentally forwarded as an action. Pressing `s` during any game writes a `.px` file and the game continues unaffected.

### The `px2svg.py` script

With `.px` files accumulating, the next step was to turn them into something visually useful. A zero‑argument script, `px2svg.py`, converts every `.px` file in the current directory into a single `snapshots.md` Markdown file. For each `.px` file, a level‑2 heading with the basename (without extension) is written, followed immediately by an SVG of the strip rendered as a row of coloured circles on a transparent background.

The visual design was debated and settled: circles of radius 4, centre‑to‑centre spacing 12 (gap = 4, exactly half the diameter), giving a loose "string of pearls" look. The canvas height is 12, width is `12 × resolution`, and the `viewBox` matches exactly. No background rectangle – the transparent canvas lets the dots float over whatever surface the Markdown is rendered on. The SVG structure is multiline with normal indentation, but contains no blank lines and no XML comments, because blank lines and comments inside an SVG block break many Markdown renderers' ability to display the image inline.

The script reads each `.px` file as raw bytes, determines `resolution = len(data) // 3`, and loops over each pixel, extracting R, G, B and emitting a `<circle>` element with `fill="rgb(r,g,b)"`. The output overwrites `snapshots.md` entirely. On completion, a short summary is printed to stderr; on an empty directory, it exits silently.

### The bullet‑trail fix in Stack

During the snapshot testing, a long‑standing visual bug in Stack was noticed and fixed in the same breath. The bullet trail gradient was inverted: the tail was brightest and the head was dim. In `Stack._render`, the intensity calculation was changed from `intensity = (i + 1) / 21.0` to `intensity = 1.0 - i / 20.0`, making the bullet head full brightness and the tail fade to near‑black. The fix was a single line in the Python reference.

The session produced:

The visual identity of the platform is now generated directly from the running game with no mockups, no Photoshop, and no manual redrawing. The stripshot is the truth.
