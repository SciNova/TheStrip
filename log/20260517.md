# 17 May 2026 – DeepSeek 3.2 Expert – SimonSays rebuilt; audio architecture overhaul

### SimonSays complete rewrite

SimonSays was found to be fundamentally broken. The game was rebuilt from scratch around a four‑state machine (`PLAYBACK`, `INPUT`, `RESULT`, `COMPLETE`) with all booleans removed. A master sequence of 120 tones is generated once in the constructor and never destroyed — the old `buildStage()` (which created a new random sequence every level, the root cause of all failures) is now empty. Steps are consistently 1‑based throughout; no `-1` sentinels, no extra tracking variables. Input evaluation is split into `process()` (pure correctness check) and `feedback()` (immediate tone + flash), with crowd reactions (`LEVEL_COMPLETE` / `LEVEL_FAIL`) shared from Stack after a 4‑second defer. Timeout and wrong answers restart the current level; level 120 triggers `GAME_COMPLETE`. The first‑tone‑skipping bug is fixed by a forced `display(sequence[0])` in the `playLevel()` override.

### Standard Simon tones added to SoundEvent

Eight new entries were added to the `SoundEvent` enum as platform‑standard tones, not game‑specific sounds: `SIMONSAYS1`–`SIMONSAYS4` (modern minor‑key set: 415, 310, 252, 209 Hz) and `SIMONSAYS1_ORIGINAL`–`SIMONSAYS4_ORIGINAL` (1978 major‑key bugle fanfare: 330, 277, 220, 165 Hz).

### Synth class (dormant)

A `Synth.hx` file was created containing the `Waveform` enum (`SINE`, `SAWTOOTH`, `SQUARE`, `TRIANGLE`), the full 24‑parameter `SynthPreset` typedef (mirrors pfxr’s parameter set with `@:range`, `@:units`, `@:default` metadata), and a `Synth` class holding a static `presets` array indexed by `SoundEvent` enum order. The `Synth.play(event)` method wraps pfxr’s `playSound()`, receiving the engine and `AudioContext` via constructor injection. Draft `SynthPreset` entries for Stack and Simon tones are prepared but the system is not yet wired into the live audio pipeline.

### Audio playback class renamed; browser conflict fixed

The JavaScript class `Sound` was renamed to `Audio`. The browser’s `HTMLAudioElement` constructor conflict was resolved by using `new window.Audio(url)` internally — our class remains named `Audio`. The Haxe extern was renamed from `extern class Sound` to `extern class Audio`, and `App.hx` now exposes `audio:Audio` with `audio.play(event)`. The old `app.sound` property is gone, clearing the name `Sound` for a future enum rename.

### Audio preloading replaces lazy loading

The lazy‑loading pattern in `Audio.js` was removed. The constructor now preloads all samples from the `SoundEvent` enum, tracks progress with a local `readySamples` counter, and sets a public `isReady` boolean when all audio elements have settled (loaded or failed). Missing files reach an error state and are simply never played.

### Non‑negotiable technical debt (remaining)

Two architectural items are deferred but mandatory for a finished product: (1) the full `Audio`/`Wave`/`Synth` hierarchy with user‑toggleable 8‑bit/Arcade audio modes, and (2) sample variation pools for frequently repeated sounds (especially Stack’s crowd reactions). These are correctness requirements, not optional polish.
