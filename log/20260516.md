# 16 May 2026 – DeepSeek 3.2 Expert & Claude Sonnet 4.6 – API refined, DisplayObject pipeline, sound enum, Stack explosions and luminance correction

A deep overhaul of the core API removed every half‑baked abstraction, leaving only what every game actually needs. The `Game` class was stripped to a single level‑management primitive (`playLevel()`), pure setters (`setLevel`, `nextLevel`), and the `defer` mechanism. The `SoundEvent` enum and a language‑agnostic `Sound` extern replaced string‑based audio. A `DisplayObject` base class with three alignment modes (`CENTER`, `FORWARD`, `BACKWARD`) gave every visual object its own fixed‑size pixel buffer and a uniform `update()`/`render()` contract. Stack gained a bullet trail and a full 3D‑to‑1D dot explosion with alpha fade, and the final rendering step now applies perceptual luminance correction for balanced brightness across colours. All existing games were updated to the new API.

### Game class cleaned
- Removed `startLevel`, `startNextLevel`, `retryLevel` and all level‑advancing logic.
- Introduced `playLevel()` as the sole action method – calls `buildStage()`, resets level time, unpauses.
- Added pure setters `setLevel(n:Int)` and `nextLevel()` that only mutate the level counter.
- `Game` now provides exactly three things: level counter, per‑level timer, and the `playLevel()` orchestration.

### Sound system standardised
- Defined a flat `SoundEvent` enum (25 events) covering all common game audio moments.
- Created an `extern class Sound` with a single `play(event:SoundEvent)` method; the JS implementation uses the enum value as the filename (`LEVEL_COMPLETE.mp3`).
- `App` constructor now takes `name:String, resolution:Int, sound:Sound` and sets `sound.app = this` for folder resolution.

### DisplayObject rendering pipeline
- `DisplayObject(app, size, alignment)` base class with a pre‑allocated `pixels` array and `update()`/`render()`.
- Three alignment modes: `CENTER` (symmetrical), `FORWARD` (head at position, extends toward larger indices), `BACKWARD` (head at position, extends toward smaller indices).
- `render()` writes directly into `app.pixels`, skipping black pixels (transparency).
- Stack objects mapped: `Dot` (CENTER, 21 px), `Bullet` (BACKWARD, 20 px trail), snake chain (FORWARD).

### Bullet trail
- Fixed 20‑pixel gradient trail from full bullet colour to just above black, computed in `Bullet.update()`.
- Trail length constant (bullet speed currently fixed), alignment BACKWARD places it behind the head.

### Dot explosion
- Pre‑allocated 21‑pixel odd‑length buffer reused for both alive and exploding states.
- `explode()` records the time; `update()` animates a half‑circle of particles with radius expansion (fast deceleration) and alpha fade.
- Exploding dot freezes at its last alive position; snake head advances to next solid dot; rendering draws frozen explosion first, then alive chain.
- Cleanup: dots with `alpha == 0` filtered out of the snake.

### Perceptual luminance correction
- Added `DisplayObject.correctLuminance(pixel:Array<Int>):Array<Int>` with scaling factors tuned for the target display (Samsung S10+ OLED: red 0.38, green 0.28, blue 1.0).
- Correction applied at the final blit in `render()`, balancing apparent brightness and optical size across red/green/blue dots.

### Games updated
- Stack, Pacman, and SimonSays all refactored to use `playLevel()`, `SoundEvent`, and the new rendering pipeline.
- All compile cleanly; Stack verified running with correct sounds, trails, and explosions.

### Documentation
- Log entries from Jan–Feb 2026 polished and formatted for consistency and readability.
- DevLab.md Game API section rewritten to reflect the actual API with code signatures and explanations.
